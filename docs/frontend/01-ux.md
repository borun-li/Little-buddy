# UX — 离线情绪陪伴小伙伴 P0 原型（本地网页，假数据）

- **Author:** fe-ux #1 · **Status:** draft
- **Named user:** the builder themself first: alone at a laptop, wants to say how the day went, out loud or typed, with Wi‑Fi off and nothing leaving the machine; later anyone in the same spot (plane, no signal)
- **Surface:** web
- **Requirements:** docs/frontend/00-requirements.md (REQ-001..008, assumptions A1–A6 taken as given)
- Product class: visual / showcase, single page (project-context.md). Flows, structure and states only: no colour, font or icon.

## 1. Pages
| Page | Job (one sentence) | Serves | Form — why |
|---|---|---|---|
| PAGE-001 | Say a line and see the companion reply and feel it with you | REQ-001, REQ-002, REQ-003, REQ-004, REQ-005, REQ-006, REQ-007, REQ-008 | list — a chat log with a composer; the companion stays pinned beside it, so every reply and mood change is seen together |

## 2. Navigation
- **Global:** nothing — one page, no menu, no header actions.
- **Contextual:** a hint line by the talk button, only for mic problems; typing dots only while a reply is pending.
- **Where am I:** always the same page; reload is the only reset (A5).
- **Keyboard:** input focused at open; Tab goes input → talk button; Enter sends; holding Space on the focused talk button records; Esc cancels a recording.

## 3. Flows
### FLOW-001 — Type a line, see it understood
- **Serves:** REQ-001, REQ-003, REQ-004, REQ-005
- **Steps:** 1. Type in the focused input 2. Enter 3. Own turn shows, input clears 4. Typing dots 5. Reply; companion takes the line's mood
- **Success:** reply ≤ 1 s, mood settled ≤ 1 s later, newest in view
- **Failure:** none: fake layer cannot fail
- **Cancel:** clear the input before Enter
- **Recovery:** reload gives the empty state
- **Boundary:** empty line → nothing; Enter during a pending reply → ignored, text kept

### FLOW-002 — Hold to talk
- **Serves:** REQ-002, REQ-003, REQ-004
- **Steps:** 1. Hold 按住说话 (or Space on it) 2. Button shows listening, with seconds 3. Release 4. Next preset line is own turn (A1) 5. As FLOW-001
- **Success:** own turn ≤ 1 s after release
- **Failure:** mic refused, absent, busy → hint by the button
- **Cancel:** release off the button, or Esc → nothing added, audio dropped
- **Recovery:** hold again, type
- **Boundary:** hold < 0.5 s → "说得太快啦，按住久一点。"; 60 s → sends itself

### FLOW-003 — First use of the mic
- **Serves:** REQ-002
- **Steps:** 1. First press 2. Browser asks for the mic; nothing records; hint shown 3. Allow 4. Hold again (FLOW-002)
- **Success:** the next hold records
- **Failure:** Block → refused hint; typing works
- **Cancel:** prompt ignored or dismissed → hint stays, typing works, nothing waits on it
- **Recovery:** allow in the address bar, then hold; or type
- **Boundary:** already allowed → straight to FLOW-002

## 4. Page details
### PAGE-001 — Talk with the companion
| State | User sees | Words | Can do next |
|---|---|---|---|
| loading | after a send: own turn, typing dots under it; send and hold paused ≤ 1 s | screen reader: "小伙伴正在回复" | keep typing (text kept) |
| empty | companion `neutral`; empty log with a hint; input focused; no `reply` hook (A4) | "想说什么都可以。按住说话，或者直接打字。" · "聊天只留在这台电脑上，刷新就清空。" | type or hold |

| permission | prompt open: hint, no recording. Refused (`NotAllowedError`): hint stays on each press | "请在浏览器弹窗里允许麦克风，再按住说话。" / "麦克风没打开。可在地址栏左侧允许，或者直接打字。" | answer prompt; type |

### Companion moods (what the user should read; fe-ui decides the look)
| `data-mood` | Reads as | Never reads as |
|---|---|---|
| neutral | here, listening, waiting for you | asleep, bored |
| pleasant-high | smiling, happy with you | over the top |
| pleasant-low | calm, content beside you | sleepy |
| unpleasant-high | worried, tense with you | angry at you |
| unpleasant-low | sad with you, gentle | crying hard, pitiful |

- The mood changes when the reply appears, never at send: it reacts with its answer.
- Each mood differs by expression, not colour alone; screen readers hear the mood in the companion's name, e.g. "小伙伴，难过".
- Rich motion: each mood has its own continuous movement. Reduce motion on (REQ-006): expression and colour only, swapped without movement; typing dots become static "…".
