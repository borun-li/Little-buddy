## `web/js/health-watch.js`
Does: Q-012 warming state machine. createHealthWatch({health, onChange, now, timers}) → {state, start, failed(code), stop}; state {canSend, canVoice, waking, hint}. Checks at open and every 2 s until bonsai and stt are ready; a failed check = bonsai down; 30 s down → hint stillDown; awake for 4 s only if a not-ready hint was shown; failed('not_ready'|'unavailable') resumes checks. onChange fires only when the state changes (no re-announce per poll).  Used by: `web/js/app.js`
Q-026: tts is its own part: onTts(on) fires only when it changes, ttsReady getter, ttsFailed('not_ready'|'unavailable') marks it not ready and resumes checks; after bonsai+stt are ready checks go on every 2 s until tts is ready (no tts field = ready); never a hint, never part of state.
Invariants: pure, clock and health() injected.  Tests: `tests/health-watch.test.js`
Traps: Q-027: talk-button.js createTalkButton({onPress}) calls onPress first in press() (app.js: speaker.stop()), before isPaused and the mic. app.js's isPaused callback shows the hold hint (voiceNotReady / warming / unreachable) and returns true, so a blocked hold records nothing. Enter while blocked keeps the text and repeats the hint.

## `web/js/breath.js`

## `web/js/speaker.js`

A reading that ends early (failed or refused part, FND-020) aborts its controller, so the part asked ahead is cancelled. Exports silentWav.  Used by: `web/js/app.js` (say after addReply and setMood; stop at send, press to talk (inside isPaused) and onClear; unlock at the first pointerdown/keydown)
Invariants: DOM-free, everything injected; never touches text, mood or hints; Q-026: app.js passes isEnabled (toggle AND tts ready) and onActive(bool) (reading started/ended, drives the toggle's speaking look).  Tests: `tests/speaker.test.js`, `tests/speaker-toggle.test.js` (page wiring), `tests/fnd-i2-r1-fix.test.js`
Speaker toggle (Q-026, CMP-007): .speaker-toggle + #speaker-tip in the caption slot of `web/index.html`, styles in `web/css/page.css`, state in renderSpeaker() of `web/js/app.js` (speakerOn true at open, not saved; not-ready = bare #i-volume, aria-pressed keeps the choice).

## `server/`
Does: Node gateway, no npm dependency (03 DES-001..010, DES-016..023): serves `web/`, GET /api/health ({ready, stt, bonsai, tts}), POST /api/respond ({reply, mood, lang, crisis, speech}), POST /api/transcribe, POST /api/speak (WAV); supervises three children (companion-stt, llama-server, companion-tts). Increment 2 files (be-developer #5): `server/tts.js` (createTts queue client of companion-tts; speechParts reply → spoken parts), `server/crisis.js` (isCrisis fixed zh/en phrase rule), `server/name.js` (cleanName), crisis/name prompts in `server/prompts.js`, crisisReply in `server/bonsai.js`.  Entry: `server/main.js`:main  Used by: npm start, npm run setup (--warm-only); the page via `web/js/companion-client.js`
Invariants: listens on 127.0.0.1 only; error bodies are {"error": code} with the 6 codes of `server/errors.js`:CODES (unknown /api/* → 404 bad_request); stdout is one JSON log line per event and never carries line, history, reply, transcript or audio; deadlines respond 15 s, transcribe 12 s (`server/config.js`:CONFIG); stops only the PIDs it spawned; `server/main.js`:route never throws (a throw in the request listener kills node and both children, FND-001), a malformed request-target → 400 bad_request. llama-server runs with --cors-origins none, --no-slots and a per-run LLAMA_API_KEY (child env, never logged); every gateway call to it sends the Bearer key, /health is keyless. ready never waits for tts (A18); missing TTS files (`server/config.js`:missingTtsFiles) only print paths + TTS_HINT and leave tts down, chat starts anyway. A crisis turn (isCrisis on this line only) always returns 200 with a reply containing 988, even when Bonsai is down or fails (UD-1 (a)); the crisis verdict, names and spoken text are never logged. Names are cleaned server-side (any length string; non-string → 400). A child that exits not via stop() gets one zh+en stderr line from `server/supervisor.js` (cause = first error line of its stderr tail, the warm error, or code/signal); child_gave_up at the restart cap.  Tests: `tests/server-unit.test.js`, `tests/server-fakes.test.js`, `tests/server-boot.test.js`, `tests/server-live.test.js` (be-tester); `tests/dev-increment2.test.js` (be-developer #5/#6 unit checks, run with node --test, not in npm test)
Traps: importing `server/main.js` does not start it (entry guard). llama-server is started directly, never via `samples/bonsai-models/gguf/start.sh` (that script downloads). Every Bonsai request carries the sampling params and enable_thinking false (`server/bonsai.js`:post). The mood call falls back to neutral; only the reply call can fail a turn. toMessages appends RECALL (`server/prompts.js`) to the last user message when the window holds an earlier user line; it is never stored, logged or counted by windowOf (Bonsai's template rejects a non-first system message). `server/log.js` is the JSON logger. tts queue (FND-013/015/020): one line outstanding at a time; the slot stays busy from the write until the helper answers that id or -1 (-1 → failed); an in-flight abort or 10 s timeout settles the caller at once but writes nothing, and the late answer frees the slot and is dropped; a queued item whose request is aborted is never written; more than 4 queued → the oldest gets unavailable; no answer within 30 s of the write → SIGKILL, supervisor restart, slot and queue unavailable. Crisis list: adding a zh phrase means adding the Traditional forms of its characters to TRAD_FOLD. speechParts reads SENTENCE from `server/bonsai.js` (one regex for shaping and reading); en parts spell digits (988 → nine eight eight).

## `stt/`
Does: Swift package (argmax-oss-swift 1.1.1 exact), two executables. companion-stt: resident WhisperKit transcriber, stdin {"id","pcm16"} line → stdout {"id","text","lang","ms"} or {"id","error"}; first line {"event":"ready"}. companion-tts (increment 2): resident TTSKit Qwen3-TTS reader, --voice (serena default via TTS_VOICE), stdin {"id","text","lang"} → stdout {"id","wav"(base64 PCM16 mono 24 kHz),"ms","audio_ms"} or {"id","error":"bad_request"|"ttskit"}; maxNewTokens 120 with no chunking (.none as TextChunkingStrategy: a bare .none is nil and means sentence chunking; ≤ 9.6 s audio per request); zh/en prompt caches warmed at start.  Entry: `stt/Sources/CompanionSTT/main.swift`, `stt/Sources/CompanionTTS/main.swift`  Used by: `server/stt.js`, `server/tts.js`
Invariants: WhisperKitConfig / TTSKitConfig download false with explicit model and tokenizer folders (never online; TTSKit would fetch the tokenizer if tokenizer.json were missing, so the gateway checks it before spawning); energy gate (≥ 3 frames of 0.1 s with RMS > 0.02) before decoding, since 1.1.1 hard-codes noSpeechProb 0; after decoding, isNoise (detected-language logprob < -0.5 AND every segment a temperature fallback) → text "" lang null (FND-002); zh output goes through ICU Hant-Hans; audio stays in memory.
Traps: build with `swift build -c release --package-path stt`; a new binary's first model load can take minutes (ANE compile; 53 s measured 2026-11-14 with models already compiled by whisperkit-cli), so leave stt sources alone unless needed. Non-JSON stdout lines are ignored by `server/stt.js`.
